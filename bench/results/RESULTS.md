# vectorized-math benchmark results

Generated by `bench/report.py after --before before` from `bench/results/{before,after}-{ccl,sbcl}.tsv`
(raw measurements, one line each; `bench/bench.lisp` writes them, `bench/run.sh TAG` runs both
implementations; `bench/cutoff.lisp` measures the MKL/Lisp crossovers, output in `cutoff-{ccl,sbcl}.txt`).

**What is measured.** Nanoseconds per element (array section; the scalar section: per call), the best of 2-7
repetitions of about 30 ms each (one call for the slowest cases).  `cl:` loop = a typed `cl:` loop written
for the case (arrays declared, `(speed 3) (safety 0)`, allocating its result array(s) like the operator does;
note that for `(signed-byte 64)` it wraps silently on overflow where `vm` computes the exact integer, and for
`T` it is plain generic arithmetic).  vm = the operator as shipped (`vm:+` ... called through its public
function); vm, Lisp kernel = the same with MKL switched off (`vm.impl::*mkl-available*` NIL); vm, MKL forced =
the cutoff of `+ - * /` set to 0.  Sizes 1, 16, 256, 4096, 65536, 10^6, 10^7 elements.

**Machine.** Intel Core i7-5930K (Haswell-E, 6 cores / 12 threads, AVX2), Linux 6.8, Intel oneAPI MKL 2026.2 (`libmkl_rt.so.3`,
default threading), SBCL 2.6.2, Clozure CL 1.14 (v1.14-71-gf3cc1d75: 1.14 plus the pull requests listed in the README's Known Issues).
The machine was shared with other jobs: load average 2 to 4 during every run (see the `#` lines of the .tsv
files), so absolute times carry a few percent to 20% of noise; ratios within one run are more reliable.
"before" is the code before the tuning described below, "after" the code after it (the `sqrt` and complex double rows of CCL were
re-measured alone after the last change, with the same program).

Tuning (details in the README, "Performance"): non-consing division kernels (CCL: re-implementation
of CCL's algorithm, SBCL: open-coded CL call), correctly rounded `sqrt` through the C library on CCL, the
data range of `(signed-byte 64)` arrays for `+ - *`, `float` with a literal prototype, `ash` of an array by a
scalar, `speed 3` for the integer pair kernels, MKL cutoffs from `bench/cutoff.lisp`, a faster kernel lookup.
